SUMMARY: The most important finding: the plugin keeps its live working state in $.store, which is one pretty-printed 5.3 MB JSON file shared by every Claude Code process. The file is at 96% of its 4 
MiB cap, and every get or set reads, parses, stringifies and rewrites the whole file (measured about 14 ms per get and 38 ms per set). The cost lands on the paths that matter: every prompt waits on 
two read-modify-write cycles, every model step rewrites the file, and the prune that runs when a write hits the cap reads every key one at a time, about 34 s. On the token side, prompt_cache_key is 
random for each pi process, so Reflector retries re-send about 29k uncached tokens (6 cache hits in 72 retries in the bench cache). The compacted memory also prints the newest user request twice, 
which efficiency.md E4 deliberately leaves alone. Standing costs in the main conversation are small: COMPACTION_BRIEFING is about 69 tokens and is cached, and the fixed memory boilerplate is about 
600 tokens.
