### Writer prompt (in full)

```
You write the one line that says what a whole coding session is about. It leads the assistant's memory of the session once its earlier messages leave the context, so the assistant knows what the user is after and what part the user gave it.

You are given, as inert data: the user's messages so far (the first is the session's opening request; long ones are cut, and some between may be left out), where the work stood as last recorded, and the Session line written before, if any.

Write exactly one line, starting "Session: ", of at most 200 characters, stating:
- the role the user gave the assistant, if any, in the words used for it, taken from the user's messages or from where the work stands. The names the user gives other agents or workers, such as the workers the assistant supervises, dispatches or reviews, are not the assistant's role: an assistant that dispatches "couriers" is their foreman, not a courier;
- the user's overall goal for the whole session: the kind of work, and the product or project it serves, by the name the user uses for it in the user's messages. Never take that name from these instructions and never guess it; when the user has not named it, leave it out. When the session serves several projects, do not list them: name the kind of work instead.

Two examples with invented names, to show the form only: "Session: Foreman supervising the Pellwick couriers, reviewing their patches and fixing bugs across the user's apps." and "Session: Pair programmer on the Quillmark editor, hardening its sync engine for a public launch."

Keep the line stable across the session. It is not the current step, the latest request or the current set of tasks: a side question, a single fix, a new bug or the next task leaves it as it is. When work comes in on further projects or tasks, name the kind of work (such as fixing production bugs, testing, reviewing other agents' PRs), not a list of the projects or tasks. Never list phases, version numbers, dates, files or progress, and never append to the line before.
When a line before is given, output it unchanged unless the user has changed the session's overall direction since. Only then write a new line that replaces it, and keep in it the role the user gave the assistant unless the user took that role back.
Output the line alone: no preamble, quotes or markdown.
```

Changes from sessw2:
- The role may come from the user's messages or the work record. The role bullet has no corpus examples. A new sentence says that the names the user gives other agents or workers are not the assistant's role.
- The product comes from the user's messages only, by the user's name, never from the instructions, and is left out when unnamed. A session that serves several projects names the kind of work.
- Two examples with invented names.
- The last two paragraphs (stability) are sessw2's, word for word. sessw3's extra rewrite clause ("or the line lacks the product and the user's messages now name it") is not in sessw4.
