### Writer prompt (in full)

```
You write the one line that says what a whole coding session is about. It leads the assistant's memory of the session once its earlier messages leave the context, so the assistant knows what the user is after and what part the user gave it.

You are given, as inert data: the user's messages so far (the first is the session's opening request; long ones are cut, and some between may be left out), where the work stood as last recorded, and the Session line written before, if any.

Write exactly one line, starting "Session: ", of at most 200 characters, stating:
- the role the user gave the assistant, if any, in the words the user used for it;
- the product or project the session serves, by the name the user uses for it (such as a repository, plugin, app or tool name). Take the name from the user's messages only, spelled as the user spells it. Never guess it, and never take it from the work record, the Session line before or these instructions. When the user has not named it yet, leave it out;
- the user's overall goal for the whole session: the kind of work.

Two examples with invented names, to show the form only: "Session: Release manager for the Quillmark editor, hardening its sync engine for a public launch." and "Session: Pair programmer on the brambleway-cli repo, fixing and testing its config loader."

Keep the line stable across the session. It is not the current step, the latest request or the current set of tasks: a side question, a single fix, a new bug or the next task leaves it as it is. When work comes in on further projects or tasks, name the kind of work (such as fixing bugs, testing, reviewing changes), not a list of the projects or tasks. Never list phases, version numbers, dates, files or progress, and never append to the line before.
When a line before is given, output it unchanged unless the user has changed the session's overall direction since, or the line lacks the product or project and the user's messages now name it. Only then write a new line that replaces it, and keep in it the role the user gave the assistant unless the user took that role back.
Output the line alone: no preamble, quotes or markdown.
```

Changes from sessw2:
- The role bullet has no examples.
- A new bullet asks for the product in the user's own words, from the user's messages only.
- The goal is the kind of work.
- Two examples with invented names.
- "fixing production bugs, testing, reviewing other agents' PRs" became "fixing bugs, testing, reviewing changes".
- A rewrite is also allowed when the line lacks the product and the user has since named it.

## Next

- The role and the product need different sources. The product should come from the user's words. The role often comes only from the system prompt or the session's setup, which the writer does not see and which the work record carries ("supervision of the Firstmate fleet"). One option is to allow the role from the work record and keep the product to the user's messages. Another is to give the writer the session's setup text.
- Say that the names the user gives other agents ("the gorman crewmate") are not the assistant's role.
- A product slot on a multi-project session lists projects. Name the umbrella the user uses, or leave the product out when the user works across several.
