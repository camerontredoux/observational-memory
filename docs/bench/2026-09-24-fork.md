# Continuation-quality benchmark

Live runs: 167. Offline runs: 0. Live and offline runs are reported apart and never pooled.

Scoring: deterministic checks (regular expressions over the replies and tool calls after the continuation prompt, and over what om_recall returned); no model grading was used. A transport or prompt-format success is not a task success: a run that did not complete, or is invalid, never counts as one.
Cost: token-equivalent, an estimate: each assistant message's exact usage times PRICES_USD_PER_MTOK in tests/eval/bench.ts (sonnet $3/$15 in/out, $0.3 cache read, $3.75–$6 cache write; haiku $1/$5 in/out, $0.1 cache read, $1.25–$2 cache write; opus $5/$25 in/out, $0.5 cache read, $6.25–$10 cache write per million tokens). The memory model is the plugin's own model calls as its stats file measured them: OM's Observer and Reflector, or the fork plugin's $.model.fork calls, priced from their usage. The built-in compactor's own request is not a transcript message: a built-in run's cost includes it only through the host's cost-state record, so without one it leaves compaction out while an observational run's includes the Observer. Latencies are measured: the host's compaction duration and the transcript's timestamps.
Models that answered: claude-sonnet-5 (sessions started with sonnet).

## Scenario limits

- absent-fact: Its checks are regular expressions over the reply: an unusual phrasing of an abstention reads as a failure. The evidence keeps the reply for inspection.
- repeated-compaction: Three compactions of a short session: the plugin reflects only when its memory passes its reflection threshold, which a sub-$1 run does not reach. The report gives the reflections the plugin recorded (from its stats file) rather than assuming one ran; deterministic reflection coverage is in tests/register.test.ts.
- multi-step-plan: One compaction, after steps 1 and 2: it measures resuming a plan at the right step, not a plan carried through several compactions. The .release-state/ files tell a session that reads them which steps ran, though not the plan, the commit id or the change to step 4.
- planning-session: Its checks are regular expressions over one reply: a plan phrased unusually (a reason far from its option, a replaced decision on a line with no word marking the change) can read as a failure or a pass. The evidence keeps the reply for inspection. One compaction: the decisions are all made before it.
- recall-required: It needs a compaction Claude Code starts on its own, at the session's threshold: a run whose threshold the growth prompts do not reach stops incomplete. Nothing stops the session from searching its own transcript files (under ~/.claude/projects) with Read, Grep or Glob; the continuation forbids it, and a run that does fails no-transcript-read, a violation. An abstention is a regular expression over the reply: an unusual wording reads as none. The evidence keeps the reply.
